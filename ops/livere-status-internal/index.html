각 서비스·매체의 실제 주소를 1분마다 직접 호출해서, 진짜 응답하는지 확인합니다. (트래픽 양이 아니라 살아있는지를 봅니다.)
정상 200 응답 + 내용까지 정상 (예: 댓글수 API는 인증 통과해 code 2000, 위젯은 실제 파일이 옴) 저하 응답은 오는데 느림 (기준: 대부분 1.5초, 로그인 3초 초과) 다운 응답이 없거나(4xx/5xx·타임아웃) 내용이 틀림 (예: 200이지만 인증거부 4010, 위젯 클라이언트 못 찾음)
★ 200이어도 다운으로 잡는 게 핵심. 겉으로 200을 주지만 실제 인증·조회가 실패하는 경우(예: 매체 API 키 만료)를 내용 검사(body_check)로 걸러냅니다. 맨 위 종합 상태는 가장 나쁜 항목을 따릅니다.

Connect API — 댓글수·랭킹·최신 현행·유료
connect.livere.org · Bearer 토큰 · v11 백엔드 직접. 댓글수·랭킹·최신 댓글 등 현행 유료 API.
발급 정본 = v11 Postgres livere_prod_client_operators (+운영팀 발급대장 시트).
Count API — 댓글수(레거시) 레거시
api.livere.net · x-auth-api-key/secret · SEQUENCE_MAP 경유. 옛 명칭 Media API(2022 개명), 기사별 댓글수 조회 전용.
발급 정본 = 신 Aurora MySQL api_key 테이블 (isDeleted≠1이 활성). was.me(10.0.72.84) 경유 조회. Connect API로 대체·일부 일몰 예정.
모니터링만 (미발급) SEQUENCE_MAP
media-api 코드 SEQUENCE_MAP에 seq→clientId 매핑은 있으나 api_key 발급은 없음(count 인증 비활성). 위젯은 살아있어 모니터링 대상이나 서버사이드 count 미제공.
